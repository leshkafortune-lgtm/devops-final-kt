# Архитектура системы WorkoutApp

## Описание
WorkoutApp — это веб-API для управления тренировками, развёрнутое через Docker Compose. Система обеспечивает CRUD-операции над данными о тренировках с использованием PostgreSQL для хранения и Redis для кэширования. Входная точка — Nginx API Gateway.

## Компоненты

### 1. Клиент (Browser)
Веб-браузер пользователя, отправляющий HTTP-запросы к системе.

### 2. API Gateway (Nginx)
Контейнер `workout-gateway` на базе nginx:alpine. Слушает порт 80, проксирует запросы к сервису API на порт 8080. Обеспечивает единую точку входа и возможность масштабирования.

### 3. Основной сервис (.NET 8 Web API)
Контейнер `workout-api`. Реализует бизнес-логику и REST endpoints (`/workouts`, `/workouts/{id}`). Использует Entity Framework Core для работы с БД и StackExchange.Redis для кэширования.

### 4. База данных (PostgreSQL 16)
Контейнер `workout-db`. Хранит постоянные данные о тренировках в volume `db_data`. Доступен внутри сети Compose по адресу `db:5432`.

### 5. Кэш (Redis 7)
Контейнер `workout-redis`. In-memory хранилище для быстрого доступа к часто запрашиваемым данным (список тренировок). TTL кэша — 5 минут.

## Схема взаимодействия
Client → Nginx (:80) → .NET API (:8080) ⇄ PostgreSQL (:5432)  
                                   ⇅  
                                 Redis (:6379)

## Обоснование выбора дополнительных компонентов
Выбран **Redis** (кэш), так как система ориентирована на чтение списка тренировок при редких изменениях. Очереди сообщений (RabbitMQ/Kafka) не нужны из-за отсутствия асинхронных задач. Объектное хранилище (MinIO/S3) избыточно, так как работа ведётся только со структурированными данными.
